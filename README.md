# Космические Рейнджеры 3: Дети Эльтана

> **Каноническая ветка: `master`.** Этот README — живая точка входа для людей и AI-агентов. Перед любой разработкой сверяйтесь с текущим `master`, а не со старым чатом или локальной копией.

Настоящий KR3-концепт: мрачная, сюжетная, системная космическая RPG/strategy sandbox в духе **Space Rangers**, но с упором на умную дипломатию, динамическую галактику, войну в нескольких измерениях и объединение несовместимых рас.

## 🤖 Agent Quick Start

Для ChatGPT, Wingman и других AI-разработчиков порядок чтения перед изменениями:

1. `README.md` — текущее состояние и правила координации.
2. `docs/ROADMAP.md` — живой план и ближайшие приоритеты.
3. `docs/KR2_MECHANICS_PARITY_MATRIX.md` — обязательный backlog механик SR2/SRHD и сильных модов.
4. `docs/PROJECT_CONSTITUTION.md` — неизменяемые архитектурные/дизайнерские принципы.
5. GDD/lore/quest docs — контекст конкретной системы.
6. `game/webgl/` — **канонический playable runtime**; изучить фактический код и тесты до планирования изменений.
7. `.github/release-decision.json` — намерение по выпуску следующей версии.

### Правила совместной работы агентов

- `master` — единая каноническая ветка; не плодить параллельные версии проекта без явной необходимости.
- Полный KR3 WebGL runtime в `game/webgl/` нельзя заменять, уменьшать или откатывать к scaffold/демо.
- Перед работой всегда получать свежий `master` и проверять, что другой агент уже не реализовал выбранную механику.
- Один агентный проход = один небольшой связный инкремент, который можно независимо проверить.
- Переиспользовать существующие системы; не создавать вторую реализацию уже существующей механики.
- Новая механика считается завершённой только когда она реально подключена к playable runtime и/или соответствующему production-модулю и имеет проверку.
- После успешного изменения обновлять документацию состояния, если изменились фактические возможности игры или следующий приоритет.
- Не копировать защищённые тексты/ассеты SR2 или модов; переносить идеи механик в оригинальную реализацию KR3.
- Не коммитить `node_modules`, временные build outputs и прочий генерируемый мусор.

## High Concept

Спустя 250 лет после КР2 галактика снова стоит на краю уничтожения. Махпеллы вернулись, а их оружие **«Исказитель Реальности»** стирает целые системы. Единственная надежда — древнее пророчество гаальцев о **Детях Эльтана**, существах, способных объединить несовместимое и создать невозможный альянс.

Игрок — рейнджер-визионер, который должен собрать этот альянс, найти Келлера, войти в глубокий гипер и вернуть в обычный космос силы, ушедшие в тень чёрных дыр.

## Core Dimensions (Z-Mechanic)

- **Обычный космос** — дипломатия, торговля, исследования, политика Коалиции.
- **Глубокое гиперпространство** — война Келлера, аномалии, скрытные операции, диверсии.
- **Режим Чёрной Дыры** — сюрреалистичные теневые миры, древние флоты, утерянные технологии.

## Main Pillars

- **Smart Diplomacy System** — переговоры, психологические профили, блеф, подкуп, баланс интересов.
- **Alliance Grid** — управление внутренним напряжением альянса и риском раскола.
- **Dynamic Guerrilla War Map** — координация атак в обычном космосе, гипере и теневых зонах.
- **Text Quest Legacy** — большие ветвящиеся квесты в традиции классических КР.
- **Living Ranger Sandbox** — торговля, оборудование, репутация, контракты, NPC, фракции, войны и системные события должны взаимодействовать между собой.
- **Solo + Online split** — сюжетная кампания отдельно, галактическая сеть отдельно.

## Modes

### 1. Solo Campaign

Главный MVP: сюжетное оффлайн/псевдо-оффлайн прохождение с глубоким лором, дипломатией, сюжетными развилками, поиском Келлера, сбором альянса и войной против Махпелл.

### 2. Galactic Network (Online)

Отдельный долгосрочный трек: PvE спецоперации, PvP гипер-арены, кланы и базы, живой рынок, кооперативные рейды в чёрные дыры.

## WebGL Verification Gate

Для изменений, затрагивающих WebGL, перед коммитом должны успешно пройти как минимум:

```bash
npm install --prefix game/webgl --no-audit --no-fund --package-lock=false
npm test --prefix game/webgl
npm run build --prefix game/webgl
```

Также выполнять `node --check` для изменённых/runtime JavaScript-файлов. Конкретный агент обязан учитывать дополнительные проверки, уже существующие в репозитории и governing skill.

## Living Documentation Contract

README и Roadmap — часть состояния проекта, а не архивные заметки. Агент должен обновить их, когда его проверенный инкремент меняет:

- реально доступные игроку механики;
- завершённый milestone/roadmap item;
- следующий наиболее логичный приоритет;
- структуру canonical runtime или процедуру проверки;
- правила handoff между агентами.

Документация не должна заявлять о фиче как о готовой раньше, чем она присутствует в `master` и прошла соответствующие проверки.
